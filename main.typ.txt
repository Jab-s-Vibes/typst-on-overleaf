= The goal

We write papers in Typst and submit LaTeX. The editing loop is: author in
Typst locally, convert to LaTeX, compile with a Springer template. Our
collaborators live on Overleaf. Wouldn't it be nice if the Overleaf project
itself compiled the Typst source — so the shared project _is_ the Typst
document?

Overleaf runs `latexmk` in a sandboxed container and serves whatever lands in
`output.pdf`. `latexmkrc` is arbitrary Perl executed inside the sandbox, and
it can redefine the compile command itself. The plan was simple: upload a
Typst binary, point `$pdflatex` at it, done.

It was not done. This is the journey.

= Part 1 — the hijack

Overleaf invokes roughly:

```sh
latexmk -cd -f -jobname=output -synctex=1 -interaction=batchmode -pdf main.tex
```

`-jobname=output` means the PDF preview is `output.pdf` regardless of what
produced it. The `$pdflatex` override wins over the `-pdf` flag:

```perl
$pdflatex = './typst compile main.typ.txt output.pdf 2>output.log #';
```

The trailing `#` turns latexmk's appended arguments into a shell comment.
`$go_mode = 1` forces a rebuild every time (latexmk only tracks `main.tex`).

Keep a stub `main.tex` as the project's main document — it's never actually
compiled.

= Part 2 — the sandbox fights back

*`/compile` is noexec.* Uploaded files land in `/compile` (the compile
directory), and executing anything from there fails with `Permission denied`
— even a plain `#!/bin/sh` script. We copied binaries to `/tmp` and executed
them there. That worked.

*There is no `xz`.* Our first typst tarball was `.tar.xz`. The sandbox has
gzip but not xz:

```
tar (child): xz: Cannot exec: No such file or directory
```

Re-packed as `.tar.gz`. The upload pipeline strips the executable bit; `tar`
restores it on extraction.

*Rust binaries abort at startup.* SIGABRT, exit code 134, _no panic
message_. Not musl, not glibc, not typst 0.14 vs 0.15, not static vs dynamic.
A 10 KB C hello world ran fine. A 550 KB Rust hello world aborted. Same
signature every time: the process starts, runs for a few microseconds, and
kills itself with SIGABRT — silent.

This is where we stopped guessing and started reading.

= Part 3 — reading the sandbox's mind

Overleaf's compile service is open source (`overleaf/clsi`). It ships its
seccomp profile: `seccomp/clsi-profile.json`. The headline:

```json
"defaultAction": "SCMP_ACT_ERRNO"
```

*Default-deny.* Everything not explicitly allowed returns `EPERM`. The
allowlist is \~164 syscalls. The interesting omissions:

```
poll, ppoll, epoll*, socket, recv, send  -> BLOCKED (no IPC, no network)
getrandom, statx, rseq, io_uring_setup   -> BLOCKED
clone (only with CLONE_*NAMESPACE flags) -> BLOCKED  — regular threads OK
clone3                                   -> allowed
openat, read, write, mmap, fcntl, futex   -> allowed
```

We built a local emulator from this profile: a tiny static binary that
installs the same filter (default EPERM, same allowlist, same clone arg rule)
via seccomp(2), then execs the target. Suddenly every abort was reproducible
locally, under strace, in seconds.

= Part 4 — the poll(2) story

The strace of a Rust hello world under the emulator:

```
poll([{fd=0,events=0},{fd=1,events=0},{fd=2,events=0}], 3, 0) = -1 EPERM
rt_sigprocmask(SIG_BLOCK, ...)
tkill(SIGABRT)
```

Three file descriptors, zero events, zero timeout — a probe. It's Rust std's
`sanitize_standard_fds()`, called in `sys::init` at _every_ Rust program
startup, which polls fds 0,1,2 to detect closed standard streams. The code:

```rust
while libc::poll(pfds.as_mut_ptr(), 3, 0) == -1 {
    match errno() {
        EINTR => continue,
        EINVAL | EAGAIN | ENOMEM => break 'poll,  // fall back to fcntl
        _ => libc::abort(),                       // ← EPERM lands here
    }
}
```

`EPERM` hits the abort arm. No message, no panic — straight to `abort()`.
That's why every Rust binary died the same way.

*The fix — LD_PRELOAD a poll that lies.* `poll` is called as a libc
_function_, so it's interposable:

```c
int poll(struct pollfd *fds, nfds_t nfds, int timeout) {
    errno = EINVAL;      /* std falls back to fcntl, which IS allowed */
    return -1;
}
```

`EINVAL` is one of the tolerated errors — std breaks out of the poll path and
uses `fcntl(F_GETFD)` instead. fcntl is on the allowlist. Done.

Fun fact from the same source file: Rust std's docs literally anticipate this
sandbox — `sys/random/linux.rs` explains that getrandom “is blocked in
seccomp by default”, and on `EPERM` it falls back to `/dev/urandom`
automatically. So the blocked getrandom was a non-issue all along; only poll
aborted.

`LD_PRELOAD` requires a dynamic binary, which is why we abandoned the musl
static builds and compiled typst for glibc (built on Ubuntu 24.04 to match
the sandbox's glibc 2.39 — checked with `objdump -T` that no symbol needed
more).

= Part 5 — one more crash

With the poll shim in place, the compile _mostly_ worked, but gVisor killed
the typst process at teardown — sometimes after `output.pdf` was written,
sometimes before. A per-command `LD_PRELOAD=... typst compile ...` env
assignment didn't reach the follow-up steps, so the source-map generator ran
without the shim and aborted too (`export LD_PRELOAD` fixed that). A perl
wrapper to hide the crash made things worse: perl's `system()` returned -1
(fork failed in the sandbox) on every attempt, while backticks forked fine.

Two things got us to a stable compile:

+ `RAYON_NUM_THREADS=1` — the crash was in the rayon thread pool
  interaction; single-threaded typst compiles in \~1.5 s and doesn't crash.
+ Retry the direct invocation until `output.pdf` exists, then check it.

Real typst errors still flow to `output.log`; the compile status is reported
with a `test -s output.pdf && echo COMPILE_OK || echo COMPILE_FAILED`.

= Part 6 — source tracking: teaching SyncTeX a new dialect

Overleaf's PDF viewer does click-to-source via SyncTeX. Typst emits no
synctex. But typst _knows_ where everything is — the problem was exporting it.

*First attempt: reverse-engineer the synctex format.* We couldn't find
Overleaf's viewer code (proprietary), but the _parser_ is open —
`synctex_parser.c` in TeX Live. Reading it told us the record grammar, and
the `synctex` CLI was our oracle: hand-write a minimal `.synctex.gz`, run
`synctex view`/`edit` against it, adjust until both directions resolve.

The minimal structure that parses and works:

```
SyncTeX Version:1
Input:1:main.typ.txt
Output:pdf
Magnification:1000
Unit:1
X Offset:0
Y Offset:0
Content:
!0
{1
[1,38:x,y:w,h:0,0,0      ← page box (tag,line:column,h:v,width:height,depth)
(1,38:x,y:w,h:0,0,0      ← hbox
h1,38:x,y:w,0:0,0,0      ← void hbox
x1,38:x,y                ← boundary: this is what carries (file,line) + coords
)
]
}
Postamble:
Count:N
!24
Post scriptum:
```

Coordinates are stored as integers: _bp × 65781.76_ (equivalently pt ×
65536), origin top-left, y down — which matches typst's own coordinate
system. The boundary record (`x`) is what reverse search resolves; the box
records make it clickable. The `!` anchors and the `Postamble:`/`Count:` are
required; the parser ignores unknown trailing content per line.

*Second problem: typst's script API hides source positions.* `typst eval`
can give you an element's page and coordinates via `location()`, but not its
source span. The `query` output serializes no spans. Section headings only
got us label-line jumps — ugly and coarse.

*The real fix: a 60-line patch to typst.* The data was never hidden — the
layout keeps it. In the compiled `PagedDocument`, every `FrameItem::Text`
carries glyphs, and _every glyph_ carries its source span:

```rust
pub struct Glyph {
    pub range: Range<u16>,
    pub span: (Span, u16),   // ← the source location of this glyph
    ...
}
```

We added `typst query --map`, which walks `pages → frames → items`, and for
each text run emits:

```
/path/to/file|line|col|page|x|y|w|h
```

resolving the span to a file/line/column through `WorldExt::range`. The
generator then emits one synctex box per text run — per-paragraph, per-word
granularity, mapped to the exact source line. No label matching at all.

```
$ typst query --map doc.typ | head
/content.typ.txt|20|10|1|70.9|82.5|457.1|17.0
/content.typ.txt|27|12|1|177.9|105.2|239.4|17.0
...
```

= The result

```
typst-on-overleaf/
├── latexmkrc            # $pdflatex override, poll shim, compile+retry
├── main.tex             # stub main document (never compiled)
├── typst-…-linux-gnu.tar.gz   # typst built for glibc 2.39, patched with --map
├── pollshim.so          # makes poll(2) return EINVAL
├── synctex-gen.txt      # perl: typst query --map → output.synctex.gz
├── typst-packages/      # vendored @preview packages (no network in sandbox)
└── main.typ.txt         # this document: the blog post, self-contained
```

In Overleaf: PDF renders from Typst, click any word → jumps to its source
line in `main.typ.txt`. Both directions work.

= Lessons

+ *Never guess a sandbox.* The profile is right there in the source
  (`overleaf/clsi/seccomp/clsi-profile.json`). Build an emulator from it —
  a seccomp filter is 20 lines of C — and everything becomes reproducible
  under strace in seconds instead of one slow remote round-trip per theory.
+ *Read the standard library.* Rust std _documents_ that getrandom is
  seccomp-blocked and handles it. The abort wasn't getrandom — it was a
  three-line match in `sanitize_standard_fds` that treats EPERM as fatal.
+ *`EPERM` ≠ `ENOSYS`.* Sandboxes default to EPERM; well-behaved code falls
  back on ENOSYS and dies on EPERM. Choosing which error a blocked syscall
  returns can be the difference between a crash and a fallback.
+ *Interpose the function, not the syscall.* LD_PRELOAD can't touch a raw
  `syscall` instruction. Rust std calls `poll` through libc — interposable.
  That's the whole trick.
+ *The data was always there.* Typst's per-glyph spans are in the layout.
  The script API hides them; a small patch to the CLI surfaces them. Per-word
  source mapping wasn't impossible — it just wasn't exported.
+ *A blog post's worth of debugging boils down to: emulator, strace, and
  reading the source.*
